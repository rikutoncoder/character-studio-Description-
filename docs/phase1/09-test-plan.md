# 自動テスト・E2Eテスト計画

## テスト戦略

アプリケーションの決定的な正しさと、AI生成の非決定的な画質を分離する。

- 通常の自動テスト：固定画像、固定マスク、fake ComfyUIで高速かつ決定的に実行
- 実ComfyUI試験：Mac M4・16GB上で低頻度に実行
- 人間の画質評価：Raw/Strict比較画面から記録

AI画質が良好でも画素保持に失敗した候補は不合格とする。画素保持に成功しても要求衣装と異なる候補は採用しない。

## Unit Test

### Domain

- 確定版とAssetを更新できない。
- Candidate検証失敗時に採用できない。
- `expectedHeadVersionId`不一致時に競合となる。
- 復元が既存履歴を変更せず新版を作る。
- JobとAttemptの状態遷移が許可表に従う。
- terminal状態から不正遷移できない。
- 同じidempotency keyの再送で重複Resourceを作らない。

### Canvas / Coordinates

- Client、Stage、Image Spaceの往復変換。
- 異なるズーム、パン、Device Pixel Ratioで同一Image座標になる。
- 画像端のブラシを範囲内へclipする。
- 二値正本化で値が0/255だけになる。
- Undo/Redoでストローク差分が完全に戻る。

### Strict Composite

- マスク外変更0画素。
- featherのsupportが二値マスク内に限定される。
- 保存・再読込後もマスク外が同一。
- RGB/RGBAのチャンネル規則。
- RGBAではマスク内外を問わずalpha channelが元画像と完全一致する。
- 寸法不一致、空マスク、非二値マスクを拒否。
- 832×1216以外をOriginal Uploadとして保持し、編集・生成には使用しない。
- 基準外画像を暗黙に拡大・縮小しない。

## Property-based Test

ランダムな小型画像とマスクを生成し、次を検証する。

- `O[mask == 0] == S[mask == 0]`
- 出力寸法が入力正本と同一
- feather幅に関係なくマスク外係数が0
- 複数回合成しても各段階の保護領域が変化しない
- 任意のRaw Outputに対してマスク外変更0

## Golden Image Test

Phase 0で使用した代表ケースを、個人情報や不要な大容量を含めないテストfixtureとして選別する。

- TEST-001相当：色変更
- TEST-002相当：構造追加
- TEST-003相当：連続編集
- ハードマスクと2〜4px内向きフェザー

期待値は画像全体の単一hashだけに依存せず、マスク外0画素、寸法、チャンネル、境界帯の指標を保存する。意図したアルゴリズム更新時だけfixtureを更新する。

## Contract Test

- OpenAPIに対するrequest/response検証
- TypeScriptとPythonのenum・schema互換性
- 未知フィールド・未知SSEイベントの前方互換性
- 64bit seedの桁落ち防止
- error codeとHTTP statusの対応
- fake Generation AgentとApplication APIの契約
- モデル変更検知後に再検証されるまでJobを開始しないこと
- JobAttemptに検証済みモデルhashが保存されること

## Integration Test

- Asset stagingから確定移動、DB登録までの成功経路
- DB登録失敗時の未参照ファイル回収
- 直列キューで同時実行数が1を超えない
- Agent停止、再起動、WORKER_LOST処理
- キャンセル要求と遅延キャンセル
- SSE切断・再接続と状態復元
- 同一Jobの再試行でAttemptが追加される
- 同一seed再試行と別seed再試行の記録
- 生成中に別端末が新版を採用した競合
- 端末セッション失効後のアクセス拒否
- 最終利用から30日経過した端末セッションの拒否
- 有効な利用時に端末セッション期限が更新されること
- DBにセッショントークン平文が保存されないこと
- 30日未満、保護済み、採用済みAssetがcleanup対象にならないこと
- 30日経過した未保護の失敗・不採用Assetだけがcleanup対象になること
- 永続Assetから参照されるAssetを削除できないこと

## Playwright E2E

### PC

1. プロジェクト作成
2. 画像取り込み
3. マスク・ガイド作成
4. Job作成
5. fake Agentによる進捗
6. 三画像比較
7. 採用
8. 版履歴表示
9. 過去版から新版作成

### スマホ

1. ペアリングコードで端末登録
2. 一本指描画と二本指パン・ズーム
3. ボトムシートからレイヤー・設定操作
4. 生成開始後に画面を離れる
5. 再読込後にJob状態を復元
6. 比較と採用
7. Mac側からセッション失効後に拒否される

### 複数端末競合

1. PCとスマホで同じ先頭版を開く。
2. PCからJob A、スマホからJob Bを作る。
3. Aを採用する。
4. Bの採用が409となり、STALE表示される。

## 実ComfyUIスモークテスト

- Animagine XL 3.1、832×1216
- 色変更プリセット1件
- 構造追加プリセット1件
- 直列実行
- 実時間とシステムメモリ観測
- Raw OutputとStrict Outputの差分記録
- マスク外0画素の確認

約3分の生成と環境依存性があるため、通常のcommit単位CIには含めない。実行条件、モデルhash、workflow revisionを記録する。

## 非機能テスト

- 約3分の生成中もUI操作が固まらない。
- スマホ画面ロック・ブラウザ復帰。
- LAN一時切断・再接続。
- Asset不足、ディスク容量不足、読み取り専用化。
- SQLiteロックと異常終了からの再起動。
- 大きなブラシ履歴によるメモリ使用量。
- 自動整理前の対象件数・容量表示と、途中失敗時の参照整合性。
- ペアリングコードの期限、再利用、試行回数制限。
- Secure / HttpOnly / SameSite Cookie属性と30日rolling expiration。
- HTTP経由で認証、Asset、編集APIを利用できないこと。
- HTTPS証明書が信頼されたスマホ実機から制作フローを完了できること。
- 未信頼証明書ではペアリングへ進めないこと。
- Macとスマホに表示した証明書指紋を照合できること。
- サーバー証明書更新後も登録済みローカル認証局で接続できること。

## 完了基準

- Strict Compositeの全自動テストでマスク外変更0。
- 版競合E2Eが安定して合格。
- PCとスマホ実機で同じ制作フローを完了。
- ComfyUI停止時に確定版を失わない。
- Raw Outputを直接採用する経路が存在しない。
- Phase 0相当の色変更・構造追加を最低各1件完了。
