# M2画像編集Workspace 追加受入判定（2026-10-17）

## 判定

**Mac内のM2試作としては受入可能。全対応ブラウザ・実機性能まで含む無条件の最終受入は保留。** 前回の[自動検証記録](14-m2-acceptance-verification.md)に、HTTPS接続したiPhone Safari実機試験と修正後の再試験を加えた判定である。ComfyUI、生成ジョブ、候補採用はM2の範囲外。LAN接続は実機試験のために追加した別機能であり、M2編集機能の合格に含めない。

## 受入基準ごとの結果

1. **異なるviewport・ズーム・パン・DPRでの832×1216マスク画素一致: 合格（自動E2E）**。Desktop Chromium、Mobile Chromium、Mobile WebKitエミュレーションの各構成で、同じ画像座標のストロークをUIから入力し、保存・再読込後の全1,011,712画素を期待値と比較して一致。テストのAPI保存先はモック。iPhone実機では描画・保存・再読込を確認したが、同一ストロークの全画素比較までは行っていない。
2. **一本指から二本指への切替: 合格**。自動E2Eに加え、iPhone実機で未確定線の取り消し、全指が離れるまでの誤描画防止、二本指パン・ズームを確認。指を離す前に線が見えない不具合はライブプレビュー追加後に実機で解消を確認した。
3. **マスク消去と両ガイドの連動Undo／Redo: 合格（自動E2E・iPhone Safari実機）**。保存データでマスクと両ガイドの同一画素が一操作で消え、Undo／Redoで一緒に戻ることを確認。2026-10-18には単一のテスト専用Workspaceで実機操作と保存画素の照合を完了した（詳細は下記）。
4. **自動保存・IndexedDB復旧・再読込・409競合: 合格**。自動E2Eに加え、iPhoneで保存完了、接続停止中の「保存: エラー」、再読み込み後の確認付き復元と再保存、409時の未保存内容保持、「最新版を読み直す」と「別Workspaceとして保存」を確認。複製先 `25eeafe7-4415-4009-a7f5-2f21f2f48557` はMac側にも存在する。自動上書き・自動マージはしていない。
5. **大ストローク性能・保存時間・メモリ・IndexedDB容量: 合格（測定実施）、実機性能は未検証**。256pxブラシ・60移動ステップで約32万画素を変更。最新の自動計測ではDesktop Chromiumのpointer-up応答241ms／保存完了2,109ms、Mobile Chromium 244ms／2,111ms、Mobile WebKitエミュレーション1,120ms／2,987ms。ChromiumのJSヒープは約17→41→28MiB、WebKitは計測不可。復旧JSONは11.58MiB、Storage EstimateはChromium約0.55MiB／WebKit約25.73MiB。単発のモックAPI試験値であり、実機iPhoneの時間・メモリ・容量保証ではない。再現条件と旧測定値は[前回記録](14-m2-acceptance-verification.md)を参照。
6. **回帰・ビルド: 合格**。M1の17件を含むPython unittest 22件、Vitest 6件、Playwright 33件、Next.js production buildが合格。最新のUI・内部API転送修正後もPlaywrightとbuildを再実行した。LANスモーク試験では未認証401、HTTP案内ポートの編集API 404、ペアリング後のNext.js→localhost Python API 200、失効後401を確認。
7. **iPhone Safari実機: 合格（実施した操作に限る）**。一本指、二本指、回転、バックグラウンド復帰、タブ再開、IndexedDB復旧、レイヤー選択、両ガイド描画・保存に加え、両ガイド同時消去・Undo／Redo・再読込を確認。Safariの正確なバージョン、端末失効直後の実機拒否は未検証。
8. **Safari・Chrome・Edgeの現行版と直前メジャー版: 一部のみ検証、全体は未検証**。実際に操作したのはバージョン未記録のiPhone Safariと、Macにインストール済みのChrome 155.0.8059.84（headlessで表示・ズームのみ）。Playwright同梱のChromium／WebKitを実ブラウザ試験として数えない。Chromeの確認も全編集機能や現行／直前メジャー版の網羅ではない。Edge実機・実ブラウザは未検証。

## M1の不変性と今回の修正

保存済みAsset 20件の実ファイルSHA-256はSQLite記録と全件一致し、ImageVersion 1件、生成用Mask 0件のまま。Workspace編集がM1の確定Asset・版履歴を上書きしていないことを確認した。M1コアと厳密保持合成の実装は変更していない。

今回の実機試験で、描画中の線が見えない問題をライブプレビューで修正し、二本指移行時にはプレビューも破棄した。レイヤー選択は44px以上のタップ領域と明示的な選択状態へ修正した。Next.jsの内部API転送はPython応答を先にバッファへ読み切るよう変更し、読み取り12回の連続試験は成功。ただし、以前見られたNode/undiciのストリームassertionが長時間・高頻度の保存で再発しないことまでは証明していない。

## 2026-10-18 iPhone実機での両ガイド連動再試験

既存のiPhone Workspace `25eeafe7-4415-4009-a7f5-2f21f2f48557` を複製し、テスト専用Workspace `44e5505f-4559-4eaf-8f14-ed0d60ca876c`（初期revision 1）だけを編集した。マスクを選択し、直径256画像pxの消しゴムで白い四角の下半分を1回タップ。iPhone Safari上で保存完了を確認後、SQLiteが参照する不変PNGの画素を元データと照合した。

- revision 2: マスク7,708画素を消去。仮着色ガイド367画素、シルエットガイド991画素が同時に消え、両ガイドが重なる6画素も消えた。両ガイドの消去マスク外変更は各0画素、保存後のガイドalphaのマスク外残存も各0画素。マスク追加画素は0。
- revision 3: iPhoneでUndoして保存。マスク・両ガイドのAsset IDが複製時とすべて一致し、編集前の画像データに戻った。
- revision 4: iPhoneでRedoして保存。3つのAsset IDがrevision 2とすべて一致。Safariの再読み込み後も「保存: 完了」と消去後の表示を確認した。
- 複製元Workspaceはrevision 2のまま、確定版への変更はない。テスト専用Workspaceは検証証跡として残した。iPhone Safariの正確なバージョンは未記録。

## 2026-10-18 保存反復・実Chrome確認

通常のプロジェクトとは別の一時SQLite DBでPython内部APIとNext.js production serverを127.0.0.1に起動し、Web API経由で832×1216画像を取り込み、Workspaceを作成した。約12,141,106バイトのWorkspace応答を伴う保存・再読込をまず12回、次に新しい一時DBで100回繰り返した。フェザー値を3px／4pxで交互に変更し、保存ごとにrevisionと再読込値を照合した。100回試験では保存100件・再読込100件がすべてHTTP 200、最終revision 101、保存応答時間は最小0.104秒・最大0.125秒・平均0.110秒。確定版のproject headは不変。テスト用サーバーを停止し、一時DBを破棄した。これは短時間・単一クライアントでの試験であり、長期間の利用や同時接続時に断続的な接続リセットが再発しない証明ではない。

Macにインストール済みのGoogle Chrome 155.0.8059.84本体をheadless起動し、既存のテスト専用Workspaceを読み取り表示した。Canvas 1枚と「保存: 完了」を確認し、マウスホイールで表示倍率が約68.7%から97.4%へ変化した。ページ読込から確認まで約1.1秒。保存・タッチ・全編集機能はこのChrome試験の対象外。MacのSafari 18.3.1はバージョンを確認しただけで操作試験はしていない。Microsoft EdgeはこのMacにインストールされていない。

## 残るリスクと次の判断

- Mobile WebKitエミュレーションの大ストローク解放が約1.1秒。実機の体感とメモリを定量測定し、必要ならM2範囲で改善する。
- 対象ブラウザの実バージョン別・全編集機能の互換性、実機での端末失効後拒否、複数クライアントや長期間の反復保存を確認する。単一クライアントの100回反復は上記の通り合格した。
- この未検証項目を合格に読み替えない。M2はローカル制作の試作として利用できるが、広い端末向けの完成版として公開する判定ではない。
