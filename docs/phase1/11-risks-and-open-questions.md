# 技術リスクと未決定事項

## リスク登録簿

### R1. 生成時間とMac負荷

- 状況：通常生成約3分。生成中のシステム空き率22%、スワップ約6.62GBの観測あり。
- 影響：応答遅延、他アプリへの影響、複数Jobでの不安定化。
- 対策：同時実行数1、キュー表示、キャンセル、実測ログ、並列生成禁止。

### R2. AI生出力のマスク外差分

- 状況：Raw Outputではマスク外の約95〜98%に微小差が発生。
- 影響：連続編集で画質劣化が蓄積する。
- 対策：Raw直接採用禁止、各段階で厳密保持、マスク外0画素を採用条件にする。

### R3. マスク境界の継ぎ目

- 状況：ハードマスク境界に継ぎ目が残る。
- 影響：衣装境界の画質低下。
- 対策：二値マスク正本＋2〜4px内向きフェザー。保護側へ漏らさない。

### R4. 構造追加によるポーズ変化

- 状況：高denoiseや広いマスクで腕、手、体型が変化し得る。
- 影響：顔・体型固定という製品価値を損なう。
- 対策：シルエットガイド、denoise 0.50〜0.65、保護マスク、手動比較。将来ControlNetを検討。

### R5. 小物生成の弱さ

- 状況：細いベルト、バックルなどはpromptだけでは不安定。
- 影響：要求デザインとの不一致。
- 対策：精密マスクとガイド。自動合格にせずレビューを必須にする。

### R6. 同一seed再現性

- 状況：3つの異なるseedで成功したが、同一seed完全再現は未証明。
- 影響：「再生成すれば同じ画像になる」という期待を満たせない可能性。
- 対策：seed、model hash、workflow revision、全sampling条件を保存。完全再現をPhase 1で保証しない。

### R7. SQLiteとファイルの不整合

- 状況：DBとファイルシステムは単一トランザクションにならない。
- 影響：孤立ファイルまたは参照切れ。
- 対策：staging、hash検証、原子的移動、DB後登録、orphan recovery。

### R8. LAN公開の認証

- 状況：同一LANにも信頼できない端末が存在し得る。
- 影響：画像閲覧、Job実行、版変更。
- 対策：HTTPS必須、短時間ペアリング、端末セッション、失効、レート制限、Origin/Host/CSRF検証。

### R9. スマホブラウザの制約

- 状況：画面ロック、バックグラウンド化、メモリ回収、タッチ競合。
- 影響：編集中の未保存ストロークや進捗表示の消失。
- 対策：頻繁なWorkspace保存、Jobのサーバー実行、再接続復元、実機E2E。

### R10. ローカルからクラウドへの移行

- 状況：ローカルパスやSQLite前提がドメインへ漏れる可能性。
- 影響：大幅な作り直し。
- 対策：UUID、Storage URI、Repository/Storage/Generation Port、OpenAPI、外向きMac Agentモデル。

### R11. ディスク容量

- 状況：空き容量約60GBで、Original、Raw、Strict、Guide、Mask、Preview、複数版を保存する。
- 影響：生成途中の容量不足とAsset破損。
- 対策：Job前の容量確認、Asset重複排除、容量表示。失敗・不採用Assetは30日後に整理し、保護・採用・参照中Assetは自動削除しない。

### R12. 色空間と境界合成

- 状況：sRGB単純補間と線形光補間で境界の見え方が異なる。
- 影響：暗い縁や色ずれ。
- 対策：マスク外は常にbyte copyし、マスク内フェザーだけ比較試験して方式を決定する。

## 未決定事項

### Phase 1実装前のBlocker

現時点で未決定のBlockerはない。Phase 1ではRGBA正本のalphaを画像全体で元画像から保持する。

### 実装中に決定可能

1. inward featherの既定値を2、3、4pxのどれにするか。
2. sRGB補間と線形光補間のどちらを境界合成に採用するか。
3. 自動再試行の最大回数。
4. Undo/Redoをブラウザ再読み込み後も保持するか。
5. サポートするSafari、Chrome、Edgeの最低バージョン。
6. Apple PencilのpressureをPhase 1で使うか。
7. Jobの概算待ち時間表示方法。

### 後続Phaseまで保留

1. Supabase採用の最終判断。
2. クラウドとMac Agent間のキュー・認証方式。
3. 複数ユーザー、共有、権限。
4. 三面図生成の入力・整合性評価。
5. Blender向け資料の形式。
6. ControlNet、OpenPose、参照画像拘束の採用。
7. 自動マスク・部位認識。

## 保存期間

- 失敗した生成画像と不採用Candidateは30日間保存する。
- 保護されたCandidateは自動削除しない。
- 確定版、採用済みStrict Output、その生成根拠となる元画像・Mask・Guide・設定は、参照関係がある限り削除しない。
- 一時Preview、Job log、orphan recovery対象の細かな保存期間は実装中に決定可能な運用値として扱う。

## 設計承認後も変更管理が必要な事項

確定事項を変更する場合は、Architecture Decision Record相当の記録を追加し、理由、影響、移行方法、既存Assetへの影響を明記する。実装上の都合だけで、Raw直接採用、マスク外0画素、確定版不変、ComfyUI非公開などの原則を緩和してはならない。
